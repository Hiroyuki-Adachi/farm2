# # 1249 価格計算テストのfactory移行

## 設計

`MachineResultTest`の既存13ケースを維持し、共有fixtureのロード時に作られていた価格計算データを、テストごとの保存済みレコードへ移す。

- モデル単位の最小factoryを`test/factories`に追加する。固定IDやfixture名をfactoryに埋め込まない。
- `MachinePricingScenario`はこのテストだけがincludeする。所有者と作業者の世帯一致を`same_home:`、単価の設定先を`source:`、数量単位を`adjust:`、作業日を`worked_at:`で明示する。
- 組織・世帯・作業者・作業種別・作業・作業結果・機械・機種・単価を生成する。面積ケースだけ土地と作業土地を生成する。
- 共通の作業分類は`work_types(:work_types9)`を利用する。価格・数量の計算はこのマスタの属性を参照しないため。共有機械・世帯・作業者は他のテストと共有変更への耐性検証に必要なので残す。
- 単価ヘッダは2001-01-01と2015-03-01の2世代を生成する。作業日は2015-02-28と2015-03-01、土地面積は12.50aと23.75aを保持する。
- 通常とリースの明細を両方用意し、価格を変えて世帯一致による選択を検証する。機種別ケースには機械別ヘッダを作らない。
- `create`でvalidationとcallbackを通す。単価ヘッダには空の`details_form`を渡し、明細は明示的に作る。WorkKindには年度と価格を指定し、UUIDはモデルに生成させる。

## 実装と削除確認

最初に既存13ケースを移行して13 tests / 52 assertionsの成功を確認した。その後、リース単価、作業種別別単価優先、機械別単価優先、同じ作業・機械の時間合計の4ケースを追加した。

旧`pricing_*`の定義と参照を検索し、Rails fixtureの数値ID相当（CRC32から算出）もtest配下で検索した。数値ID参照はなかった。専用レコードは13個のYAMLファイルから削除し、fixture間の参照も残していない。全体集計への影響は全体テストで確認する。

`fixtures :all`、transactional tests、本番コードは維持する。ロード方式変更と性能計測は#1250の範囲とする。

## 検証

検証結果はPRとIssueコメントに記録する。関連4ファイルを複数seed、全体テストを単独プロセスで実行する。

- 最終全体テスト: seed 1249、1,466 tests、6,186 assertions、失敗・エラー・skipなし。単独プロセスで実行。
- RuboCop: factory・helper・MachineResultTestの15ファイル、指摘なし。
